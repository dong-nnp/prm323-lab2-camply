# Camply — Flutter Handoff Specification

**Purpose:** Implementation guidance for a Flutter developer. This Lab does not require writing Flutter code; this document defines expected layout, reusable components, states, interactions, navigation and constraints for each screen.

## 1. Global implementation rules

- Reference design: `design/DESIGN.md`; screen-level requirements: `design/screen-spec.md`.
- Android-first reference size: 360 × 800 dp. Use responsive constraints (`Expanded`, `Flexible`, `LayoutBuilder`, `ConstrainedBox`) rather than fixed absolute positioning.
- Safe areas: respect status bar, system navigation area, keyboard insets and bottom navigation (`SafeArea`). Scroll forms when keyboard is visible (`resizeToAvoidBottomInset: true`).
- Typography: Inter with Roboto/system fallback; body text ≥14 sp and support system text scaling without clipping.
- Interactions: minimum 48 × 48 dp targets; clear pressed/focus states; do not communicate state by color alone.
- Event data must come from a consistent model/source (`Campus Music Night — Oct 26, 2026 • 18:00–22:00 — Main Stadium`) and student identity (`Alex Morgan — STU-849201 — alex.m@university.edu`) so S01–S10 cannot disagree.
- Use real loading/error/success transitions. Do not fake successful registration after a failed request.
- Cancellation is treated as committed after confirmation in T01: **T07 displays a confirmation message without an Undo button** (Decision D07).
- The prototype ticket QR must be marked as a UI demonstration (`Demonstration pass`).

## 5. Responsive behavior

- **360 dp:** Reference layout. Single-column feed and list; `16 dp` side gutters; no horizontal overflow.
- **412 dp:** Keep the same information hierarchy; let cards, text containers and inputs expand flexibly via `Expanded` / `double.infinity`; do not simply scale all text or images.
- **600 dp and wider:** Center content inside a `ConstrainedBox(maxWidth: 560)` for detail/form screens (S03, S04, S05, S07, S09, S10), or use a 2-column `GridView` (`maxWidth: 840`, `crossAxisSpacing: 16`, `mainAxisSpacing: 16`) for event lists (S01, S02, S06, S08) while preserving the same 4-destination navigation model.
- **Text scaling:** Long event titles, venues and notification bodies wrap naturally. Avoid fixed-height text containers that clip.
- **Keyboard:** Registration form scrolls to focused fields; submit button is never hidden behind the keyboard.
- **Safe areas:** Bottom navigation and snackbar remain above system navigation; dialogs stay within the available viewport.
